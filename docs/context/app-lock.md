# 应用锁

应用锁是登录后的本地隐私保护层，不替代账号认证，也不把手势凭证发送到服务端。

## 数据边界

- `UserAppConfig.gestureLockEnabled` 是用户偏好配置，服务端默认值为 `false`，用于跨设备同步“希望启用应用锁”的设置。
- `UserAppConfig.userId` 由服务端根据当前登录态明确返回，客户端用它隔离当前用户的本地应用锁数据，不依赖未加载的用户实体关系。
- 当前设备的凭证只保存在本地 `AppLockStorage`，按用户使用 `app-lock:{userId}:credential` 命名空间隔离。
- 凭证由规范化后的点位序列通过 PBKDF2-SHA256 派生，包含随机 salt 和迭代次数；运行时 `unlocked` 不持久化。
- 失败次数和 30 秒临时锁定状态保存在同一用户命名空间，用于限制误操作，不作为账号安全边界。

## 状态与流程

服务端开启而当前设备没有凭证时，状态是 `missingCredential`，进入应用锁设置页完成本机设置；凭证无法解析时是 `corruptedCredential`，进入恢复流程。有效凭证进入 `ready`，解锁成功后只在当前运行时放行受保护页面。

开启流程先保存本地凭证，再更新服务端偏好；服务端更新失败时删除本地凭证。关闭流程先更新服务端，再删除本地凭证和失败状态。忘记手势时使用当前账号密码验证，验证成功后关闭偏好并清理本地状态。

## 入口

设置页的“应用锁”入口位于 `/settings/app-lock`。RootLayout 在已登录且配置加载完成后统一执行 AppLockGuard；配置加载期间不渲染受保护内容。锁定时仍允许访问应用锁设置页，以便使用账号验证恢复。开屏锁页点击“忘记手势密码”时会携带恢复入口状态直接进入旧密码验证页，无需再次点击设置页中的“忘记手势密码”。应用锁激活期间会取消应用内的浏览器后退（POP）导航，按钮触发的恢复、返回和关闭流程不受影响。
