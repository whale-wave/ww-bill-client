# iOS 快捷记账确认流程

## 用户流程

iPhone 快捷指令由背部轻点触发，依次执行截屏、本机文字识别、HTTPS POST 和打开确认地址。客户端不接收原始截图，只接收服务端草稿中的 OCR 文字与候选字段。

设置入口为 `/settings/shortcut-bookkeeping`。`/bookkeeping/import` 只负责安全领取草稿，领取完成后立即无感跳转到原有的 `/bookkeeping` 记账编辑器，不展示独立的快捷记账页面。正式记录必须经过以下动作：

1. 用地址中的一次性 handoff code 通过 POST 领取草稿。
2. 领取成功后立即清除地址栏和当前标签页中的 handoff code，并把草稿与新生成的 review code 仅交给当前的原记账页路由状态。
3. 原记账页预填可信金额、商户备注和截图时间；根据 OCR 关键词预选收支类型与一个明确匹配的现有分类。无法可靠判断时保持为空，由用户选择。
4. 快捷记账固定写入个人默认账本。用户仍可在原编辑器修改收支类型、分类、金额、备注和日期。
5. 用户点击原记账编辑器的完成按钮后，仍调用草稿确认接口创建正式记录，而不是普通新增记录接口。
6. 用户在原编辑器取消时放弃草稿，立即清除 OCR 原文、候选字段并使草稿失效。

## 官方快捷指令模板

正式模板固定请求 `https://abill.easyhappy.top/api/shortcut-drafts`，按以下顺序配置：

1. “截屏”。
2. “计算哈希”，输入选择上一步截图，算法选择 SHA-256；结果作为 `clientRequestId`。
3. “从图像中提取文本”，输入选择上一步截图。
4. “当前日期”，使用 ISO 8601 格式作为 `capturedAt`。
5. “获取 URL 内容”，方法为 POST，请求正文为 JSON：
   - `rawText`：提取的文字；
   - `clientRequestId`：截图的 64 位 SHA-256 哈希；
   - `capturedAt`：格式化后的当前日期。
6. 请求头 `Authorization` 设置为 `Bearer ` 加凭证。凭证文本必须配置成快捷指令的导入问题，提示用户粘贴鲸浪页面刚复制的凭证；公共模板中不得填写真实凭证。
7. 从响应依次读取 `data` 和 `confirmationUrl`。有值时使用“打开 URL”，无值时显示“提交失败，请检查网络或重新创建凭证”。

本地验证时使用当前页面展示的局域网请求地址。验证通过后复制快捷指令，将请求地址替换为上述生产地址，再创建 iCloud 分享链接。生产构建通过 `VITE_IOS_SHORTCUT_URL=https://www.icloud.com/shortcuts/<id>` 注入链接；只接受 `https://www.icloud.com/shortcuts/` 下的分享地址。未配置或地址非法时，页面保留“创建凭证”并自动展开手动配置。

在 GitHub 仓库变量中设置 `VITE_IOS_SHORTCUT_URL` 后重新构建客户端镜像。更新模板需要发布新的 iCloud 分享链接、替换该变量并重新构建；不能把测试凭证带入共享模板，发布前应撤销制作和验收期间使用的临时凭证。

已安装快捷指令的凭证轮换顺序为：先在鲸浪创建新凭证，将快捷指令请求头中的旧值替换为新凭证并完成一次草稿确认测试，最后回到鲸浪撤销旧凭证。不要先撤销旧凭证，否则验证失败时快捷指令将暂时不可用；设备丢失或凭证疑似泄露时则应立即撤销对应凭证，再重新安装或配置。

## 客户端安全边界

- 主账号 JWT 只用于登录后的领取、放弃和确认接口，不进入快捷指令或 URL。
- 快捷指令使用独立的 draft-only bearer credential；完整值只在创建时显示一次。
- OCR 原文和 review code 只保存在当前原记账页的路由状态中，不写入 React Query 持久化缓存；领取 code 只在草稿领取前临时进入当前标签页的 `sessionStorage`，领取成功、确认或放弃后立即清除。
- iOS 的 Open URLs 通常进入 Safari，不能依赖主屏幕 PWA 的登录状态；首次使用可能需要在 Safari 再登录一次。

## 维护提示

中转路由复用草稿领取安全校验，原记账页复用个人默认账本、分类查询和记录编辑器。服务端返回的金额、类型、商户和日期都只是候选；自动分类只在唯一规则命中时预选，不能绕过用户修改和服务端最终校验。真机验收需要覆盖目标 iOS 版本、支付宝和微信付款截图、Safari 登录回跳、连续两次背部轻点以及在原记账页取消草稿。
