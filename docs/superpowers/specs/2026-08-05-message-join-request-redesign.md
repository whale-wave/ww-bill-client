# 消息与加入申请审批页面复刻设计

**状态：** 已确认  
**日期：** 2026-08-05  
**涉及仓库：** `ww-bill-client`

## 目标

以参考软件的消息流和账本加入申请审批流程为结构基准，将鲸浪记账的 `/message` 主入口改为真实通知列表，并重做加入申请详情页。页面颜色、图标和反馈状态继续使用鲸浪记账现有主题与组件，不复制参考软件的黄色品牌视觉。

## 路由与兼容边界

- `/message` 直接展示现有 `/notifications` 数据，不再显示“新的关注 / 评论 / 系统通知”三项分类卡片。
- 现有 `/message/new-follow`、`/message/comment-list` 和 `/message/system-notify` 路由及页面保留，避免破坏历史链接和已有能力。
- `LEDGER_JOIN_REQUEST` 且通知负载可解析为安全审批地址时，显示“去处理 >>”并导航到 `/ledgers/:ledgerId/join-requests/:requestId`。
- 其他通知继续显示标题、时间和正文；没有有效目标时不渲染伪操作入口。
- 继续复用现有通知、已读、分页和加入申请审批接口，不修改后端协议。

## `/message` 消息列表

- 使用白色页面和白色导航栏，标题为“消息”，保留左上角返回。
- 每条消息采用参考图的横向结构：左侧为鲸浪记账应用图标，右侧为标题与相对时间，下一行展示正文。
- 未读状态使用主题色轻量标识，不增加参考图中不存在的大面积卡片、类型标签或独立操作按钮组。
- “去处理 >>”作为正文末尾的主题色内联操作；点击整条可处理消息或该操作都先执行幂等已读，再进入安全目标。
- 列表保留加载、失败重试、空状态、加载更多和全部已读能力；管理操作不抢占单条消息的主要视觉层级。
- 页面背景、分割线、字号和间距贴近参考图，交互色统一使用 `--ww-theme-color`。

## 加入申请详情

- 导航标题显示申请人昵称、姓名或用户名；无法取得时使用“未知用户”。
- 首个白色信息区按行展示头像、申请附言和“设置该成员的角色”，右侧内容与箭头对齐。
- 待审批且有可分配角色时，角色初始显示“请选择”；未选择角色时“同意加入”不可提交。
- 点击角色行打开底部弹层。弹层包含标题、关闭按钮，以及当前操作者可分配的角色；每项展示角色名和解释，点击即选中并关闭。
- 角色映射保持现有领域值：`ADMIN` 为管理员、`BOOKKEEPER` 为记账成员、`VIEWER` 为只读成员。
- 角色选中后显示“加入后的权限”区：
  - 所有角色均显示浏览权限“查看记账”。
  - `BOOKKEEPER` 增加记账权限“添加新记账、修改记账、删除记账”。
  - `ADMIN` 在记账权限外，增加预算权限，以及账本管理权限（基本信息、类别、标签、成员和数据导出）。
  - `VIEWER` 不显示修改类权限。
- 页面底部固定双按钮：“忽略”为次按钮，“同意加入”为主题色主按钮。移除页面上的拒绝和审批备注输入，不删除底层已有拒绝接口能力。
- 已处理、无权限、无数据、加载和失败状态沿用现有业务判定，并适配新页面外观。

## 响应与错误处理

- 提交期间锁定重复操作并显示加载状态。
- 审批成功后保留现有成功提示和返回申请列表行为。
- 请求失败时保留可见错误提示，不清除用户已经选择的角色。
- 通知已读失败不阻断安全目标导航；权限或冲突类错误继续交由现有请求层和页面反馈处理。

## 可访问性与移动端行为

- 消息项、角色行、关闭按钮和底部操作均使用语义化按钮并提供可访问名称。
- 角色弹层支持遮罩关闭、关闭按钮和 Escape/组件默认键盘行为。
- 固定底部操作区考虑安全区内边距，正文预留足够滚动空间，不遮挡权限列表。
- 保持应用现有移动端最大宽度和 `page` / `page-new` 容器约束。

## 验收

- `/message` 首屏结构与参考图一一致，展示真实通知而非分类入口，主题色为鲸浪记账蓝色。
- 加入申请详情的未选择、角色选择弹层、管理员、记账成员和只读成员状态分别对应参考图二至六的布局与信息层级。
- 不可分配的角色不出现在弹层；未选角色不能批准。
- “忽略”和“同意加入”调用现有接口，使用当前请求版本并防止重复提交。
- 旧消息子路由仍可直接访问；通知目标仍通过现有白名单解析。
- 针对消息列表、通知导航和加入审批的测试通过，类型检查、完整测试和生产构建通过。
