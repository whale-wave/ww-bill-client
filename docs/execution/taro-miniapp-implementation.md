# Taro 微信小程序首版实施记录

日期：2026-09-30。分支：`ww-bill-client/refactor/taro`。

## 目标与范围

在项目所有者生成的 Taro 4 React + TypeScript 模板内，实现现有账号密码登录、个人明细、收支记账、基础图表、发现入口和我的信息。保留现有后端接口，复用 `@ww-bill/bill-core` 金额逻辑；小程序独立封装请求和存储。Zustand 4 管登录态，TanStack Query 4 管接口数据。

共享边界按用户修正：从 Web 现有组件中抽出无状态的展示部分放入 `packages/bill-ui`，Web 与小程序分别提供 DOM/Taro 原语并保留各自的状态、请求、导航和交互；平台无关的纯类型、金额及展示规则放入 `packages/bill-core`。不能直接搬用 Web 页面或依赖浏览器 API 的组件。各页面逐块迁移，未接入公共组件的页面不算完成这一层复用。

## 任务与验收

1. 依赖与配置：接入共享包、Zustand 和 TanStack Query，按 `bill-2` 独立端口配置本机请求地址，保留可配置的真机 HTTPS 地址。
2. 请求与状态：封装可替换的传输接口和 Taro 适配器，统一处理 Bearer、分类版本请求头、HTTP 与业务错误；登录态持久化并隔离账号缓存。
3. 页面：四个常驻 Tab（明细、图表、发现、我的）和中间记账入口；登录、分类选择、按月明细与翻页、收支创建、图表汇总、用户信息形成闭环。
4. 验证：针对响应壳、鉴权、空数据与分页进行测试；执行小程序类型检查、微信构建、Web 现有检查，并检查开发者工具中的基础数据展示。真机需要可访问的 HTTPS 合法域名与可用测试账号，结果单列。

## 接口地址与验收环境

- 本地使用 `pnpm --filter miniapp dev:weapp`，开发构建默认连接 `http://127.0.0.1:4301`，字体目录默认 `http://127.0.0.1:4331/fonts`，需同时运行 Web 静态服务。生产构建必须显式设置 `BILL_MINIAPP_API_BASE_URL` 和 `BILL_MINIAPP_FONT_BASE_URL`，否则会停止而不覆盖现有产物。接口变量填写服务根地址，不含 `/api`；字体变量填写 HTTPS 静态资源目录，例如 `BILL_MINIAPP_API_BASE_URL=https://api.example.com BILL_MINIAPP_FONT_BASE_URL=https://web.example.com/fonts pnpm --filter miniapp build:weapp`。本地接口未启动时会显示网络连接失败，不能据此判定页面数据已通过真实接口验收。
- 服务端本机验收使用 `BILL_SKIP_BACKGROUND_MAINTENANCE=true pnpm start:dev`。该选项仅在 development 生效，关闭自动维护与定时任务；用户主动发出的登录、读取和记账请求照常执行。验收需使用专用测试账号，避免在共用数据库中修改真实账号的数据。
- 开发者工具游客模式仅用于页面与请求链路验证。真机需要有效的小程序 AppID、已登记的 HTTPS 请求域名、可访问的 `bill-2` 服务及测试账号；完成后应分别检查登录、四个 Tab、记账提交、退出登录和重新登录后的数据隔离。
